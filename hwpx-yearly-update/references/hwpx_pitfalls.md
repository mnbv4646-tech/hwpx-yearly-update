# HWPX 함정과 처리

`hwpx_ops.py` 가 자동으로 처리한다. 라이브러리로 직접 고칠 때 이 목록을 지킨다.

| 문제 | 증상 | 처리 |
|---|---|---|
| 섹션 수와 `header.xml`의 `secCnt` 불일치 | 한글에서 "파일 손상" | 섹션을 지우거나 더하면 `secCnt`, `content.hpf`, `META-INF/container.rdf` 를 함께 고침 (`doc.save` 가 secCnt 를 맞춤) |
| XML 선언, ZIP 순서, 압축 방식 변경 | 열리지 않을 위험 | 원본 선언 바이트를 그대로 쓰고, 원본 ZIP 항목 순서와 압축 방식 유지. mimetype 은 무압축으로 맨 앞 |
| 다른 도구로 자르거나 압축한 PDF | 글자가 `(cid:123)` 로 읽히고 △, % 가 사라짐 | `check_inputs.py check` 로 걸러 내고 원본을 쓰거나 `compact`, `split` 으로 다시 만듦 |
| 병합 칸 | 행마다 칸 수가 달라 열 순서가 어긋남 | 칸 순서가 아니라 `cellAddr` 의 열 주소로 찾음 |
| 행 추가 | 새 행 서식이 깨짐 | 같은 표의 행을 복제하고 `rowAddr`, `rowCnt` 를 다시 매김 (`fill_rows`) |
| 세로 병합이 있는 표의 행 바꾸기 | 병합 칸이 엉킴 | 병합을 풀고 행을 다시 만든 뒤 다시 병합 (`fill_rows` 의 merge_cols, group_merge_cols) |
| △ 가 따로 떨어진 글자 조각 | "△△15.78" 처럼 두 번 찍힘 | 증감 칸은 칸 단위로 글자를 다시 씀 (`set_compare_row`) |
| 숫자가 여러 글자 조각에 나뉨 | "시 3945,09" 같은 오타 | 단락 전체 글을 바꾸고 바뀐 부분만 조각에 나눠 넣음 (`set_text`) |
| 자동 합계 수식(=SUM(BELOW)) | 작년 결과값이 남음 | 글자와 함께 수식의 LastResult 도 바꿈. 복제한 행의 수식은 지움 |
| 줄 배치 정보(`linesegarray`) | 글자가 바뀐 뒤 겹쳐 보임, 표를 지운 자리에 큰 빈 공간 | 글자가 바뀐 단락의 것과 본문 단락 전체의 것을 지워서(`apply`가 자동으로 함) 한글이 다시 계산하게 함 |
| 섹션 설정(`secPr`)이 든 단락 | 지울 수 없는 빈 단락 | 섹션 첫 단락은 지우지 말고 글자만 비움 |
| 칸 첫 줄을 비워 둠 | 숫자가 한 줄 아래로 밀려 보임 | 줄 수를 원래 칸과 같게 맞춤 (`verify.py` 가 "칸 첫 줄 비어 있음"으로 알려 줌) |
| 단위가 다른 표 | 백만원 표에 천원 값 | 표마다 "(단위 : …)" 를 확인해 환산 |
| 같은 단락 안 여러 글자 모양 | 굵은 금액이 보통 글씨로 바뀜 | 숫자와 단위를 한 덩어리로 비교해 바뀐 덩어리만 그 자리 조각에 넣음 |
| 좁은 칸에 긴 글 | 여러 줄로 넘치거나 고정 높이 행에서 잘림 | 칸 너비는 바꾸지 않고 글을 줄이거나 개요 칸으로 옮김. 렌더링으로 확인 |
| 작년 글을 한 줄에 넣으려고 줄인 자간(예: -38%) | 새 글에 그대로 쓰면 글자가 겹쳐 보임 | `apply`가 고친 칸 줄의 자간을 새 글 길이에 맞춰 다시 잡음 (짧으면 0 쪽으로, 길면 작년 값까지) |
