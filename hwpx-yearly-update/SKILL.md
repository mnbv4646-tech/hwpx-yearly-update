# 한글 연례 문서 갱신

작년 HWPX 문서의 양식과 서식은 그대로 두고, 내용만 올해 원자료 기준으로 바꾼 HWPX 하나를 만든다.

## 원칙

1. **숫자는 옮겨 적지 말고 복사하고, 계산은 스크립트가 한다.** 금액은 원자료 글에서 찾은 그대로 쓰고(쉼표 포함), 증감액과 증감률, 금액 문장은 `set_compare_row`, `rewrite_sentence`, `korean_amount.py`가 만든다. 기억이나 어림으로 숫자를 쓰지 않는다.
2. **HWPX는 `hwpx_ops.py`로만 고친다.** XML을 문자열로 직접 고치거나 zip을 새로 묶지 않는다. 필요한 기능이 없으면 `hwpx_ops` 라이브러리 함수(`HwpxDoc`, `set_text`, `set_cell_text`, `fill_rows`, `save`)로 짧은 파이썬을 쓴다.
3. **업무 기준은 규칙 파일이 정한다.** 우선순위는 사용자 규칙 파일, 작년 문서의 관례, 이 skill의 기본값 순이다. 기본값으로 정한 것은 보고서에 적는다.
4. **근거 없는 내용은 만들지 않는다.** 원자료에 없는 기간, 위치, 대상, 법적 근거, 사유는 쓰지 않는다. 판단이나 추정이 들어간 문장 끝에는 `[검토 필요]`를 붙인다.
5. **블록 하나씩 끝내고 저장한다.** 블록마다 검증하고 중간본을 저장한 뒤 다음 블록으로 간다. 분량이 많아도 멈추지 말고 끝까지 간다.

## 준비

```bash
SK=<이 skill 폴더>/scripts          # 예: /mnt/skills/user/hwpx-yearly-update/scripts
pip install lxml pdfplumber pypdf --break-system-packages -q 2>/dev/null
mkdir -p work && cd work
```

받은 파일을 역할별로 나눈다. 애매하면 사용자에게 한 번 묻는다.
- **작년 문서**: `.hwpx` 1개 (양식)
- **원자료**: 올해 숫자의 근거 (예: 예산서 PDF. 여러 개로 나뉘어 있으면 색인할 때 반드시 쪽 순서대로 넣는다)
- **보조 자료**: 설명자료, 사업설명서 등 (사업 선정, 사업개요, 사유의 근거)
- **규칙 파일**: `.md`나 `.txt` 또는 프로젝트 지침. 없으면 `references/rules_defaults.md` 기본값을 쓴다.

원자료가 ZIP으로 오면 작업 폴더에 압축을 풀어 쓴다 (`python3 -c "import zipfile,sys; zipfile.ZipFile(sys.argv[1]).extractall('src')" 받은.zip`). 예산서 전체처럼 쪽수가 많은 PDF도 나누지 않고 그대로 색인한다. 압축 안 한글 파일 이름이 깨져 보여도 확장자로 찾으면 된다.

`.hwp` 파일이 오면 작업하지 않는다. 한글에서 HWPX로 저장해 다시 올려 달라고 안내한다.

## 작업 순서

### 1. 입력 점검

```bash
python3 $SK/check_inputs.py check 작년.hwpx 원자료*.pdf 보조자료*
```
- **글자 깨짐**(PDF 글꼴 손상)이 나오면 멈춘다. △와 %가 사라져 부호를 잘못 읽게 된다. 원본 PDF를 다시 받도록 안내하고, 원본이 있으면 `check_inputs.py compact` 또는 `split`(쪽 복사 방식)으로 다시 만든다.
- 용량이 크면 `compact`로 줄인다. 58MB 예산서가 9MB가 된 사례가 있다.

### 2. 원자료 색인

```bash
python3 $SK/source_index.py build IDX 원자료1.pdf 원자료2.pdf --aux 설명자료.pdf
python3 $SK/source_index.py toc IDX                 # 장, 국, 과별 인쇄 쪽 범위
python3 $SK/source_index.py pages IDX 937-950       # 인쇄 쪽번호로 글 읽기
python3 $SK/source_index.py search IDX "사업명" --range 937-950
python3 $SK/source_index.py search IDX 1,860,185    # 숫자로 찾기
python3 $SK/source_index.py search IDX "사업명" --aux   # 보조 자료에서 찾기
```
목차 쪽번호가 본문과 다르면 `toc`가 본문 기준으로 보정해 알려 준다. 이런 불일치는 최종 보고에 적는다. 목차 쪽이 없는 발췌본이면 `toc`가 구분 쪽(제목만 있는 쪽)과 쪽 위 머리글(`부서: ○○`)로 범위를 만든다 (`--key 부서`로 한 머리글만).

예산서 전체(1,500쪽 넘음)를 받았으면 쪽을 다 읽지 않는다. `toc`로 이번 문서에 필요한 장과 국의 쪽 범위부터 정하고, 그 범위만 `pages`, `pdf_rows`로 읽는다. 사용자가 국별, 장별 PDF를 원하거나 다른 대화에 넘길 파일이 필요하면 목차 범위대로 자른다 (쪽 복사 방식이라 글꼴이 깨지지 않음).
```bash
python3 $SK/source_index.py cut IDX 자른것 --match 복지보훈여성국 계속비   # 제목에 이 글이 든 항목만
python3 $SK/source_index.py cut IDX 자른것 --level 1      # 큰 장(총괄표, 세입예산서 등)과 국, 사업소, 특별회계마다 하나씩
python3 $SK/source_index.py cut IDX 자른것 --within 문화복지환경위원회   # 위원회 소관 국, 사업소마다 하나씩
python3 $SK/source_index.py cut IDX 자른것 --pages 7-17:세입총괄표   # 인쇄 쪽 범위 직접 지정
```
자른 목록(`00_자른_목록.md`)에 파일마다 인쇄 쪽과 PDF 쪽 범위가 남는다. 최종 보고에 이 표를 붙인다.

들여쓰기 단계와 숫자 열로 된 쪽(예산서 사업명세서, 세입 명세 등)은 `pdf_rows.py`로 읽는다. 쪽 글보다 행과 열이 정확하고, 사업마다 위 단계 경로를 붙여 준다.
```bash
python3 $SK/pdf_rows.py IDX 833-857 --max-level 3          # 부서, 정책, 단위, 세부사업까지 (올해 | 전년 | 증감)
python3 $SK/pdf_rows.py IDX 833-966 --find 아트 클래스 운영   # 그 사업의 경로와 아래 편성목, 산출근거
python3 $SK/pdf_rows.py IDX 833-857 --json work/rows_01.json   # 목록 표를 고를 때 코드로 거르기
```
- `L0, L1 ...`은 그 범위 안에서 행이 시작하는 위치 순서다. 세입 쪽과 세출 쪽은 들여쓰기가 달라 번호가 섞이므로 범위를 나눠 읽는다.
- `‖` 뒤는 숫자 열이 아닌 오른쪽 글(산출 근거)이다. 첫 열 - 둘째 열 = 셋째 열이 안 맞는 행이 있으면 경고가 나오니 그 쪽은 `pages`로 확인한다.
- `--changes`(증감 큰 순, `--label '^[0-9]{3}'`이면 편성목만, `--min`, `--top`)와 `--new`(전년 0인 새 항목을 가장 위 단계로 묶어 산출근거와 함께)는 목록 표 후보를 고를 때 쓴다.
- `--gone`은 전년 금액이 아래 단계 전년 합보다 큰 행(올해 없어진 하위 항목)을 보여 준다.
- `--spread`는 두 쪽에 걸친 표(왼쪽 쪽에 이름과 개요, 오른쪽 쪽에 숫자 열. 예: 계속비 사업조서)를 묶음별로 읽는다. 범위는 왼쪽 쪽부터 준다.
- 원자료가 지방자치단체 예산서면 `references/budget_book.md`를 읽는다 (구성, 재원 줄, 신규와 증감 사업 고르는 법, 계속비 위치).

### 3. 양식 분석과 작업 계획

**빈 양식 채우기**: 받은 문서가 작년 보고서가 아니라 숫자 칸을 비워 둔 올해 양식이면(표 머리 연도가 이미 올해이고 숫자 칸이 비어 있음), 연도 바꾸기와 문장 갱신은 하지 않고 비어 있는 숫자 칸만 원자료로 채운다. 표의 행과 서술, 이미 값이 있는 칸(이전 연도 열, 다른 자료 출처 표)은 건드리지 않는다. 회계별 예산규모, 세입총괄표, 세출총괄표(기능별, 조직별, 성질별), 기준인건비 세출총괄표는 예산서 앞부분에 있으니 쪽 글을 읽어 행 이름으로 맞춘다. 증감, 증감률, 구성비는 직접 계산하지 말고 예산서에 찍힌 값을 쓰고, 예산서에 없는 값(억원 단위 표 등)만 계산한 뒤 최종 보고에 적는다. 검증은 `verify.py --new 결과.hwpx --year 올해`로 한다 (`--old`를 주면 기준 연도가 하나 밀린다).

```bash
python3 $SK/analyze_template.py 작년.hwpx                 # 블록 목록
python3 $SK/analyze_template.py 작년.hwpx --block 3       # 블록 하나의 표, 칸 역할, 금액 문장
python3 $SK/hwpx_ops.py dump 작년.hwpx --from s0:p143 --to s0:p189   # 블록 전체 내용과 주소
python3 $SK/hwpx_ops.py table 작년.hwpx t42 --full        # 표 하나 자세히
```
`analyze_template.py`가 `!`로 알리는 곳(끝난 문장 뒤에 붙은 조각, 끝에서 끊긴 금액, 같은 금액 문장의 반복)은 작년 문서 자체의 오류일 수 있다. 그 문장은 `rewrite_sentence` 대신 `set_para`로 다시 쓰고 최종 보고의 "발견한 불일치"에 적는다.

블록마다 원자료 쪽 범위를 짝지어 `work/progress.json`에 적는다 (블록 번호, 이름, 문서 범위, 원자료 쪽 범위, 상태). 사용자에게 계획을 두세 줄로 알리고 바로 시작한다.

**마지막 블록부터 거꾸로 진행한다.** 뒤 블록에서 행이나 표를 넣고 지워도 앞 블록의 단락, 표 주소는 그대로라서, 처음에 작년 문서로 뽑은 dump 주소를 끝까지 쓸 수 있다. 앞에서부터 하면 블록마다 다시 dump해야 한다.

### 4. 블록마다 반복

1. **읽기**: 블록 dump 전체와 해당 원자료 쪽을 읽는다. 목록 표(신규, 증감, 계속비 등)는 규칙 파일의 선정 기준과 보조 자료로 이번 해 항목을 고른다.
2. **편집 계획 작성**: `work/plan_NN.json`. 연산 명세는 `references/edit_plan.md`.
   - 제목과 표 머리 연도: `year_shift` (`only: "headers"`가 기본. 사업 기간 같은 본문 연도는 건드리지 않음)
   - 비교표 행: `set_compare_row` (올해, 전년 금액만 주면 증감액과 증감률 계산)
   - 연도별 표(예산총액 변동현황처럼 머리에 여러 해가 나란한 표): `shift_cols`로 작년 보고서 값을 한 칸씩 오른쪽(이전 연도 자리)으로 옮기고, `year_shift`로 머리 연도를 올린 뒤, 맨 앞 올해 열만 원자료로 채운다. 가장 오래된 해는 빠진다
   - 금액 문장: `rewrite_sentence` (원래 문체와 띄어쓰기 유지)
   - 행 수가 바뀌는 표: `fill_rows` (병합 칸은 `merge_cols`, 3행 묶음은 `group_size`와 `group_merge_cols`)
   - 항목이 없어진 표: `delete_table` 후 제목 단락에 `append_text` " : 해당없음". 반대로 작년에 해당없음이던 표가 생기면 비슷한 표를 `copy_table`(`as` 별칭)로 넣고 `fill_rows`
   - 요인, 내용, 개요 칸: `set_cell`. 예산서 산출근거와 보조 자료에 있는 사실만 쓰고 금액 표기는 `korean_amount.py fmt`로 만든다. **칸의 구조는 작년 같은 칸 그대로 둔다**: 작년 칸에 있던 소제목(`∘ 사업개요`, `∘ 편성사유`)과 항목 줄(`- 위    치 :`, `- 기    간 :`, `- 내    용 :`)을 같은 순서로 쓰고, 자료로 확인한 값만 채운다. 확인 못 한 항목은 줄을 지우거나 다른 내용(산출근거 금액 나열 등)으로 채우지 말고 `- 위    치 : [검토 필요]`처럼 남긴다. `내용`은 산출근거 품목을 옮겨 적는 줄이 아니라 그 사업이 무엇을 하는지 한 구절로 쓴다 (실제 보고서 예: "방문간호사 등 전담인력에 의한 건강관리서비스 제공에 필요한 차량 구입", "환자감시모니터 등 노후장비 구입비 지원", "수목원 내 진입로 및 탐방로 주변 정비"). 품목은 대표 하나에 "등"을 붙여 묶고, 수량, 단가, 금액은 쓰지 않는다. 목적은 원자료에 있는 말로만 쓰고(예: 품목 이름의 "방제형", "벌목용"), 원자료로 무엇을 하는 사업인지 알 수 없으면 `- 내    용 : [검토 필요]`로 둔다
   - **문서에는 작년 문서에 있던 꼴의 내용만 넣는다.** 판단 근거("전년도예산액 0이라 신규"), 자료 출처, 작업 메모, 작년에 없던 소제목은 문서에 넣지 않고 최종 보고에 쓴다. 사람이 볼 표시는 `[검토 필요]` 하나뿐이고, 적용할 때 빨간 글자로 바뀐다
   - 검토의견 등 서술: 작년 문장을 문체 견본으로 삼아 `set_para`나 `insert_para`. 판단이 들어간 문장은 `[검토 필요]`
   - **작년 양식 관례를 새 행과 새 문장에도 지킨다.** 작년 표의 금액 칸이 "1,000" 아래 "시 1,000"처럼 재원 줄을 달았으면 새로 넣는 행에도 예산서 재원(`pdf_rows`의 재원)으로 같은 줄을 단다 (`"1,450\n시 1,450"`). 예산서에 재원 줄이 없는 일반회계 항목은 전액 시비라는 뜻이므로 `시 금액`을 단다 (비워 두지 않음, `references/budget_book.md`). 작년 서술에서 굵게 쓴 곳(검토의견의 금액, 사업명 등)은 새 글에서도 `**굵게**`로 표시한다. 줄 앞 빈칸("  ▸", "    -")은 견본 단락(`like`)에서 그대로 이어지니 글 앞에 빈칸을 따로 넣지 않는다. 칸 첫 줄을 빈 줄로 비우는 것은 작년 같은 칸이 그랬을 때만 한다
3. **적용**: 앞 블록 결과 파일에 이어서 적용한다.
   ```bash
   python3 $SK/hwpx_ops.py apply work/step_03.hwpx work/plan_04.json -o work/step_04.hwpx
   ```
   계획 안의 주소는 적용 전 문서 기준으로 한꺼번에 해석된다. 앞쪽 블록부터 했다면 행이나 표를 넣고 지운 다음 블록은 다시 dump해서 새 주소로 계획을 쓴다.
4. **검증**:
   ```bash
   python3 $SK/verify.py --new work/step_04.hwpx --old 작년.hwpx --index IDX --block 4
   ```
   verify 는 숫자뿐 아니라 작년 양식 관례(재원 줄, 굵게, 들여쓰기, 칸 첫 줄 빈 줄, 칸 안 소제목과 항목 줄)도 본다. [오류]는 모두 고친다. [확인]은 원인을 보고 고치거나, 정상이면 이유를 최종 보고에 적는다. 합계 행처럼 원자료에 없는 값을 직접 계산해 넣었으면 그 행이 아래 행 합과 맞는지 verify 가 확인한다. 기준 연도는 작년 문서 연도 + 1로 잡는다 (다르면 `--year`). 표의 행 수를 바꿨으면 렌더링으로 한 번 본다.
   ```bash
   python3 $SK/render_check.py work/step_04.hwpx --find "신규사업" --out work/render
   ```
   렌더링에서 "7. 검토의견" 같은 제목이 쪽 맨 아래에 홀로 남고 본문이 다음 쪽으로 넘어가면 그 제목 단락 앞에서 쪽을 나눈다 (`set_para`의 `page_break: true`, 아래 연산 명세). 쪽을 넘어가는 표의 병합 칸 글자가 잘려 보이는 것은 그림 도구의 한계이고 파일 문제는 아니다.
5. **기록**: `progress.json`에 상태와 메모를 남기고 사용자에게 한 줄로 진행 상황을 알린다. 대화가 끊겨도 이 파일과 마지막 step 파일로 이어서 한다.

### 5. 마무리

```bash
python3 $SK/verify.py --new work/step_NN.hwpx --old 작년.hwpx --index IDX
python3 $SK/render_check.py work/step_NN.hwpx --pages 1-3 --out work/render
echo '{"ops": []}' > work/plan_title.json
python3 $SK/hwpx_ops.py apply work/step_NN.hwpx work/plan_title.json -o "<올해 문서 이름>.hwpx" --title "<올해 문서 제목>"
```
전체 검증의 [오류]가 0이 될 때까지 고친다. 앞부분(블록 밖 제목 등)의 연도와 문서 속성 제목(파일 정보에 보이는 제목, verify 가 작년 연도면 알림)도 바꾼다.

## 최종 보고

`references/report_format.md` 형식으로, 사용자가 요청에 쓴 언어(보통 한국어)로 쓴다. 꼭 들어갈 것:
1. 블록별로 바꾼 내용 요약 (표 구성 변경, 새로 넣거나 지운 표 포함)
2. 적용한 기준 (규칙 파일, 작년 관례, 기본값 중 무엇이었는지)
3. 근거를 못 찾아 비워 두거나 `[검토 필요]`로 둔 곳
4. 발견한 불일치 (작년 문서 오류, 원자료 안의 불일치, 목차 오타 등)
5. 검증 결과 요약과 남은 [확인] 항목
6. 한글에서 열어 볼 곳 (행을 바꾼 표가 있는 쪽 등)

결과 파일은 사용자에게 보낸다. 중간본과 작업 파일은 보내지 않는다.
